# DISTRICT WEAR

Premium streetwear storefront with a browse-and-inquire shopping flow, a protected admin panel, and
a Netlify-free-tier deployment.

## Overview

DISTRICT WEAR is a catalogue experience, not a transactional shop. Shoppers browse in French
(default), Arabic (RTL) or English, build a cart, and send it as **one pre-filled WhatsApp
message**. There are no customer accounts, no online payments, no checkout and no shipping
calculations: payment and fulfilment are arranged in person. The shop owner manages the catalogue,
stock, collections, categories and store settings through a separate `/admin` panel.

## Stack and architecture

| Area     | Choice                                                                         |
| -------- | ------------------------------------------------------------------------------ |
| Runtime  | Next.js 16 App Router, React 19, TypeScript strict, Node 22                    |
| Styling  | Tailwind CSS v4 with CSS-variable design tokens in `app/globals.css`           |
| Data     | Supabase Postgres, Auth and Storage (`@supabase/ssr`, `@supabase/supabase-js`) |
| i18n     | next-intl v4 with `proxy.ts` routing; French, Arabic (RTL) and English         |
| Cart     | Zustand with `localStorage` persistence                                        |
| Forms/UI | react-hook-form + Zod, shadcn/ui components in `components/admin/ui`           |
| Motion   | Framer Motion and Lenis, with `prefers-reduced-motion` support                 |
| Hosting  | Netlify free tier with the open-source `@netlify/plugin-nextjs` plugin         |

- **Locale storefront:** pages live under `app/[locale]`; the next-intl proxy sends `/` to `/fr` and
  serves `/fr`, `/ar` and `/en`. The language switcher preserves the current route and query.
- **Admin island:** `/admin` is deliberately outside locale routing (`proxy.ts` matcher excludes
  `admin`, `api`, `_next`). Login is at `/admin/login`; every admin page and server action calls
  `requireAdmin()`, which checks a Supabase Auth cookie session plus the database role.
- **Supabase clients:** public reads and every admin page/action use the cookie-scoped anon client
  (`lib/supabase/`) under RLS, including the inquiry-logging RPC. The service-role client
  (`lib/supabase/admin.ts`) is server-only, reserved for a future privileged integration, unused by
  the current app, and never sent to the browser.
- **RLS is the security boundary:** `db/migrations/0004_rls.sql` grants public reads only on
  published/active catalogue rows and the singleton settings row. Writes require
  `public.is_admin()`; `inquiry_attempts` is reachable only through the `SECURITY DEFINER` function
  `try_log_inquiry()`. RLS on the anon client is the only boundary the current app relies on; if a
  service-role key is ever provisioned it must remain server-side.
- **Caching:** most storefront pages and `app/sitemap.ts` export `revalidate = 300`, so they are
  regenerated by ISR at most every five minutes. Admin changes also call `revalidatePath`. No paid
  cache or CDN service is used.

## Prerequisites

- Node.js 22 (the same version pinned in `netlify.toml`) and npm (bundled with Node).
- A Supabase project (the free tier is sufficient) with its project URL and anon key. The
  service-role key is OPTIONAL and not needed for this branch.
- A Git repository and a Netlify account for deployment.
- No paid plugins, vendors or services are required.

## Local setup

1. Install dependencies from the lockfile:

   ```bash
   npm ci
   ```

2. Create your local environment file:

   ```bash
   cp .env.example .env.local
   ```

3. Fill in `.env.local` using the [environment variable table](#environment-variables). Find the
   Supabase URL and keys under **Project Settings → API**. Use a random value for
   `INQUIRY_RATE_SALT`; leave `NEXT_PUBLIC_SITE_URL` at `http://localhost:3000` locally.

4. In your Supabase project's **SQL Editor**, run these files **in order, once, on a fresh schema**:

   1. `db/migrations/0001_profiles.sql`
   2. `db/migrations/0002_catalog.sql`
   3. `db/migrations/0003_settings_inquiries.sql`
   4. `db/migrations/0004_rls.sql`
   5. `db/migrations/0005_storage.sql`
   6. `db/seed.sql`

   Migration `0003` creates the singleton `public.settings` row and the inquiry tables; `0005`
   creates the public `product-images` storage bucket. The seed loads a realistic launch catalogue.

5. Create an admin user. In **Authentication → Users**, add an email/password user, then copy its
   UUID and grant the admin role in the SQL Editor:

   ```sql
   insert into public.profiles (id, email, role)
   values ('<auth-user-uuid>', '<admin-email>', 'admin')
   on conflict (id) do update set role = 'admin', email = excluded.email;
   ```

   There is no public sign-up path; an authenticated user without `role = 'admin'` is signed out by
   `/admin/login`.

6. Start the development server:

   ```bash
   npm run dev
   ```

7. Visit `http://localhost:3000/fr`, `/ar` and `/en` for the storefront, and
   `http://localhost:3000/admin/login` for the admin panel. `/` redirects to `/fr` through the
   next-intl proxy.

8. In `/admin/settings`, set the live WhatsApp number used for order messages and decide whether
   inquiry logging is on. These values live in the settings row, not in environment variables;
   keep `NEXT_PUBLIC_WHATSAPP_NUMBER` in step 3 identical so the footer link matches.

## Environment variables

Every variable below appears in `.env.example`. `NEXT_PUBLIC_*` values are inlined into the browser
bundle, so they must never contain secrets.

| Variable                        | Purpose                                                                                                                              | Example                            | Server-only? |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- | ------------ |
| `NEXT_PUBLIC_SUPABASE_URL`      | Supabase project URL used by the browser clients, admin server actions, image URLs and build-time prerendering.                      | `https://your-project.supabase.co` | No           |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon key for RLS-guarded public reads and the inquiry RPC.                                                                  | `your-anon-key`                    | No           |
| `SUPABASE_SERVICE_ROLE_KEY`     | OPTIONAL / reserved: currently unused by app code; admin actions use anon + RLS. Never prefix with `NEXT_PUBLIC_`.                   | `your-service-role-key`            | Yes          |
| `NEXT_PUBLIC_SITE_URL`          | Canonical base URL for metadata, canonical/hreflang tags, sitemap, robots and OG images. No trailing slash; falls back to localhost. | `http://localhost:3000`            | No           |
| `NEXT_PUBLIC_WHATSAPP_NUMBER`   | WhatsApp checkout fallback when the settings row is unavailable/invalid; the footer link is built from this value directly.          | `212600000000`                     | No           |
| `INQUIRY_RATE_SALT`             | Server-only salt for the hashed inquiry rate key. Falls back to `NEXT_PUBLIC_SITE_URL`, then `district-wear`.                        | `change-me-to-a-random-value`      | Yes          |

Notes:

- The WhatsApp number is **E.164 digits only**: 8–15 digits, no `+`, spaces or punctuation. The
  authoritative value for order messages is edited in the singleton settings row via
  `/admin/settings`; the environment variable is the checkout fallback and is read directly by the
  footer link. Set both to the same production number.
- Inquiry logging is toggled in that same settings row. No environment variable enables or disables
  it, and there is no logging-flag variable to copy into Netlify.
- Changing `INQUIRY_RATE_SALT` resets all inquiry rate-limit buckets. Keep it stable in production.

`npm test` creates an embedded Postgres instance with `@electric-sql/pglite`, adds minimal Supabase
`auth`/`storage` shims and roles, applies migrations `0001`→`0005` plus `db/seed.sql`, and exercises
`anon`, `authenticated` and admin behaviour. It needs **no live Supabase project and no network
access**; environment-dependent unit tests stub their variables. `npm run dev` remains available for
local browsing.

## Storefront behaviour

- The cart is persisted in `localStorage` under `district-wear-cart` (version 1) with Zustand.
  Hydration is deferred until after mount to avoid server/client mismatches; no account is needed.
- Price and stock are revalidated against Supabase before checkout. Stale or unavailable lines are
  surfaced to the shopper with an explicit update action, excluded from the subtotal, and block
  checkout until resolved. A removed variant must be cleared by the shopper.
- Checkout produces **one compact WhatsApp message** with a `DW-` reference, French product and
  colour names (regardless of the shopper's locale), French-formatted prices, a total and the shop
  number from the settings row (or the env fallback). It opens a `https://wa.me/<digits>?text=…`
  link; at most 20 lines are accepted.
- The same reference, items and total are sent to `POST /api/inquiries` as an optional side channel.
  It always returns `204`: declined logs and failures never break the WhatsApp hand-off.
- Inquiry logging ships **disabled** in the settings row. When enabled, the Postgres function
  `try_log_inquiry()` caps writes at five per ten minutes per hashed client key; no extra vendor is
  involved.

## SEO

- `lib/seo/metadata.ts` emits per-locale canonical URLs, `hreflang` alternates (including
  `x-default`), OpenGraph/Twitter tags and Moroccan locale codes.
- `app/opengraph-image.tsx` generates the OG image; `app/icon.png` supplies the favicon.
- `components/seo/json-ld.tsx` renders structured data through `safeJsonLd()`, which prevents
  `</script>` breakout.
- `app/sitemap.ts` lists all three locales for static pages plus published product and collection
  slugs; `app/robots.ts` allows crawling, disallows `/admin` and points to the sitemap. Both use
  `NEXT_PUBLIC_SITE_URL`.

## Netlify deployment

1. Connect the repository to Netlify. The framework is detected as Next.js; `netlify.toml` supplies
   the build command (`npm run build`), publish directory (`.next`), Node 22 and the free
   `@netlify/plugin-nextjs` plugin. No paid plugin is needed.
2. In **Site configuration → Environment variables**, set the five non-service-role variables from
   the table above using production values. `INQUIRY_RATE_SALT` remains optional and server-only;
   set `NEXT_PUBLIC_SITE_URL` to the real production URL (custom domain or
   `https://<site>.netlify.app`) with no trailing slash. Only add `SUPABASE_SERVICE_ROLE_KEY` if a
   future privileged integration is added. Never prefix server-only variables with `NEXT_PUBLIC_`.
3. Confirm the production Supabase project is reachable and the URL/anon key are correct **before
   starting the build** (see the launch gate below).
4. Deploy. Verify `/fr`, `/ar`, `/en`, `/admin/login`, `/sitemap.xml` and `/robots.txt`.
5. `netlify.toml` adds `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` and
   `Permissions-Policy` headers on `/*`, plus immutable one-year caching for `/_next/static/*`.
   Everything stays in `netlify.toml`; no `public/_headers` file is needed. Do not add Netlify
   redirect rules: locale routing is owned by next-intl and a redirect will fight it.

### Launch gate: build-time Supabase reachability

`NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` must be present **and the Supabase
project reachable during `npm run build`**. Prerendered pages read the catalogue and settings at
build time; if the project is paused, unreachable or the keys are missing/wrong, those pages bake in
empty states until the 300-second ISR refresh. The sitemap is affected too: product and collection
slugs can be absent until a later refresh. Fix the values or wake the project, then trigger a fresh
deploy rather than waiting for ISR. This is a hard gate for launch.

### Launch gate: Netlify IP header trust

Inquiry rate limiting prefers `x-nf-client-connection-ip`. Netlify's edge must overwrite or strip
any client-supplied value of that header so a caller cannot rotate the 5-per-10-minute cap. On
non-Netlify hosts, strip the header at your own edge or proxy before it reaches the app; otherwise
`x-forwarded-for`/`x-real-ip` are used as fallbacks and the cap can be bypassed.

## Troubleshooting

| Symptom                                 | Check / fix                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Locale redirect does not happen         | `/` is redirected to `/fr` by next-intl in `proxy.ts`, not by a Netlify rule. Check the proxy matcher and remove any host-level redirect that shadows it. `/admin` and `/api` are intentionally outside locale routing.                                                                                                                                               |
| Cannot access `/admin`                  | The email must exist in Supabase Auth **and** have `role = 'admin'` in `public.profiles` (run the SQL in step 5). Non-admin sign-ins are signed out and redirected to `/admin/login`. Confirm the migration `0004` policies.                                                                                                                                          |
| Images missing or broken                | Migration `0005` must create the public `product-images` bucket. URLs are built as `<NEXT_PUBLIC_SUPABASE_URL>/storage/v1/object/public/product-images/<storage_path>`; verify `storage_path`, bucket visibility, upload permissions and the `**.supabase.co` / Unsplash entries in `next.config.ts`. An invalid URL falls back to `/images/product-placeholder.svg`. |
| WhatsApp link has the wrong number      | Use 8–15 digits only, no `+`. The `/admin/settings` row wins for checkout; the footer reads `NEXT_PUBLIC_WHATSAPP_NUMBER` directly, so update both for live traffic. An empty or invalid number produces no checkout link.                                                                                                                                            |
| Inquiry logging appears disabled        | Logging is off by default. Enable it in `/admin/settings` (settings row), not through an environment variable. Confirm `try_log_inquiry()` exists and the setter saved the flag. The API always returns `204`, so a declined or rate-limited log is silent; `INQUIRY_RATE_SALT` changes reset buckets.                                                                |
| Empty catalogue or sitemap after deploy | This is the build-time Supabase gate above: ensure the URL/anon key are correct and the project reachable, then redeploy. ISR (300s) can refresh pages later, but a bad build should be fixed, not waited out. Also confirm products/collections are published and RLS policies from `0004` are installed.                                                            |

### Accepted platform limitations (documented at launch)

- **Raw 404 shell:** Next 16 with a top-level `[locale]` layout renders unknown URLs as an
  `__next_error__` shell with no localized header/footer until hydration. The response status is
  already 404 and the localised not-found page appears after hydration. This is an accepted platform
  limitation, not a broken deployment.
- **Motion trade-off:** `initial={{opacity:0}}` on revealed content keeps main content hidden until
  hydration. Without JavaScript, revealed content remains hidden. Global reduced-motion CSS and
  zero-duration motion protect users who prefer reduced motion; it is a deliberate
  performance/polish trade-off.
- **Sandbox npm install warning:** in restricted/sandboxed environments, install scripts for
  `@swc/core` and `@parcel/watcher` may fall outside the allow-list. This is a non-blocking install
  observation; `npm ci` still installs the packages and builds succeed.
